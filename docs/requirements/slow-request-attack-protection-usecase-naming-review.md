## 1. 用例命名规范标准

### 1.1 命名最佳实践

| 规范 | 说明 | 示例 |
|-----|------|-----|
| **R1** | 以动词开头 | ✅ 处理用户登录<br>❌ 用户登录处理 |
| **R2** | 使用主动语态 | ✅ 系统检测攻击<br>❌ 攻击被检测 |
| **R3** | 格式：动词 + 对象 | ✅ 拦截恶意请求<br>❌ 恶意请求拦截 |
| **R4** | 从参与者视角出发 | ✅ 管理员配置白名单<br>❌ 白名单配置 |
| **R5** | 避免技术术语 | ✅ 添加可信地址<br>❌ 配置 CIDR 白名单 |
| **R6** | 保持简洁 (3-7词) | ✅ 封禁恶意客户端<br>❌ 对多次违反慢请求检测规则的客户端执行自动封禁操作 |
| **R7** | 单一目标 | ✅ 封禁恶意客户端<br>❌ 检测违规并封禁客户端 |

### 1.2 常见动词库

| 动作类型 | 推荐动词 |
|---------|---------|
| 业务操作 | 处理、发送、接收、提交、创建、更新、删除 |
| 检测/判断 | 检测、识别、验证、确认、判断 |
| 阻止/防护 | 拦截、阻止、封禁、拒绝、阻断 |
| 管理 | 配置、管理、维护、更新、重载 |
| 查询 | 查询、检索、获取、查看 |

## 5. 实施建议

### 5.1 优先级

| 优先级 | 操作 | 原因 |
|-------|-----|------|
| P0 | 采用方案 A | 最小修改，快速规范化 |
| P1 | 统一动词使用 | 提高一致性 |
| P2 | 完全采用方案 B | 长期优化目标 |

### 5.2 实施步骤

1. **阶段一：快速修复**
   - 为所有用例名称添加动词
   - 简化过长的名称
   - 拆分复合用例

2. **阶段二：一致性优化**
   - 统一同类用例的动词
   - 确保命名模式一致
   - 审查技术术语使用

3. **阶段三：完整规范化**
   - 从参与者视角重命名
   - 减少技术术语
   - 添加用例别名（如需要）
